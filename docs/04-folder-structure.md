# HeavyHire — Step 4: Folder Structure

One repo, three parts:

```
HeavyHire/
├── apps/
│   ├── web/          → the website (Next.js): renter, vendor AND admin screens
│   └── api/          → the server (Express + Prisma)
├── packages/
│   └── shared/       → code used by both (and later by the mobile app)
├── docs/             → these planning documents
├── package.json      → root scripts: "pnpm dev" starts web + api together
├── pnpm-workspace.yaml → tells pnpm about apps/* and packages/*
├── tsconfig.base.json  → TypeScript settings shared by all parts
├── .gitignore
└── README.md
```

> **Why one repo?** You change the API and the screen that uses it in one go,
> and both use the same types, so a typo in a field name is caught before you run anything.

---

## 1. `packages/shared` — written once, used everywhere

```
packages/shared/src/
├── index.ts            → exports everything below
├── constants.ts        → booking statuses, their EN/HI labels, limits (max photos etc.)
├── money.ts            → toPaise(1000) = 100000, formatRupees(944000) = "₹9,440"
├── pricing.ts          → calculatePrice(): rent + transport + GST + commission
│                         (the website preview and the server use the SAME math)
└── schemas/            → form/request rules with Zod (used for form checks AND API checks)
    ├── auth.ts         → phone must be 10 digits, OTP 6 digits
    ├── machine.ts      → add/edit machine fields
    ├── booking.ts      → create booking fields
    └── vendor.ts       → vendor sign-up fields
```

### The pattern inside every module (3 files)

Example: `src/modules/bookings/`
```
bookings.routes.ts   → URLs:  router.post("/", requireUser, handler)  (handler calls parse(schema, req.body))
bookings.service.ts  → logic: check availability, calculate price, save to DB
bookings.schema.ts   → request rules (mostly re-exported from packages/shared)
```
**Rule:** routes only read the request and send the response.
All real work happens in the **service**, which makes it easy to test and reuse
(e.g. the WhatsApp webhook calls the same `acceptBooking()` as the vendor screen).

## 3. `apps/web` — the website

Everything (renter, vendor, admin) is in one Next.js app. The `[locale]` part of the
URL switches language: `/en/search` or `/hi/search`.

```
apps/web/
├── messages/
│   ├── en.json              → all English text
│   └── hi.json              → all Hindi text
├── public/                  → logo, icons, category images
├── src/
│   ├── app/[locale]/
│   │   ├── layout.tsx       → header, bottom nav, language switch
│   │   ├── page.tsx         → HOME: pick machine type + location
│   │   ├── search/page.tsx  → results list
│   │   ├── machines/[id]/page.tsx   → machine details
│   │   ├── book/[machineId]/page.tsx → 3-step booking (When → Where → Pay)
│   │   ├── login/page.tsx   → phone + OTP
│   │   ├── bookings/
│   │   │   ├── page.tsx     → my bookings
│   │   │   └── [id]/page.tsx → booking status + timeline + call button + review
│   │   ├── profile/page.tsx
│   │   │
│   │   ├── vendor/          → VENDOR AREA (4 tabs)
│   │   │   ├── layout.tsx   → tabs: Machines · Bookings · Earnings · Profile
│   │   │   ├── join/page.tsx         → become a vendor (upload 3 docs)
│   │   │   ├── machines/page.tsx     → my machines
│   │   │   ├── machines/new/page.tsx → add machine (one screen)
│   │   │   ├── machines/[id]/page.tsx → edit + blocked dates
│   │   │   ├── bookings/page.tsx     → requests & jobs (accept/reject, status buttons)
│   │   │   ├── earnings/page.tsx
│   │   │   └── profile/page.tsx
│   │   │
│   │   └── admin/           → ADMIN AREA (4 tabs + stats)
│   │       ├── layout.tsx   → tabs: Approve · Bookings · Users · Settings
│   │       ├── page.tsx     → stats
│   │       ├── approve/page.tsx
│   │       ├── bookings/page.tsx
│   │       ├── users/page.tsx
│   │       └── settings/page.tsx
│   │
│   ├── components/
│   │   ├── ui/              → Button, Input, Card, Badge, BottomSheet, Spinner
│   │   ├── layout/          → Header, BottomNav, LanguageSwitch
│   │   ├── machines/        → MachineCard, PhotoGallery, PriceBox, CategoryGrid
│   │   ├── booking/         → StepWhen, StepWhere, StepPay, StatusTimeline
│   │   ├── maps/            → MapPicker (choose site on map)
│   │   ├── vendor/          → MachineForm, BookingRequestCard
│   │   └── admin/           → ApprovalCard, DataTable
│   │
│   ├── lib/
│   │   ├── api.ts           → one fetch helper: adds token, handles errors
│   │   ├── auth.ts          → save/read login tokens
│   │   ├── razorpay.ts      → opens Razorpay checkout
│   │   └── upload.ts        → uploads photos to Cloudinary
│   │
│   ├── hooks/               → useAuth, useMachines, useBooking... (TanStack Query)
│   ├── i18n/                → language setup (next-intl)
│   └── proxy.ts             → sends /search to /en/search (Next.js 16 renamed middleware → proxy)
├── .env.example
├── next.config.ts
├── package.json
└── tsconfig.json
```
